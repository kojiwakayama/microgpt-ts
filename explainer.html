microgpt.ts — Explained

A complete tour of every component in a from-scratch GPT transformer implemented in ~340 lines of dependency-free TypeScript, ported from Andrej Karpathy's microgpt.py.

Lines of code: ~340
Dependencies: 0
Params: ~21 k
Training steps: 1 000
Task: name generation

What Happens When You Run It

From cold start to generated names — every phase in order

1

Phase 1 — Boot & Data Load

The runtime checks if input.txt exists. If not, it fetches ~32 000 first names from Karpathy's makemore dataset on GitHub and writes them to disk. This only ever happens once.

The file contains one name per line — entries like emma, olivia, ava. Each name becomes one "document" the model will learn to reconstruct.
2

Phase 2 — Vocabulary & Tokenisation

All names are joined into one string and every unique character is collected, then sorted. Because the dataset is English first names, this gives you the 26 lowercase letters, a–z.

A special BOS (beginning-of-sequence) token is appended as token ID 26, bringing the total vocabulary size to 27. Each character is mapped to an integer: 'a' → 0, 'b' → 1, … 'z' → 25, BOS → 26.

The model learns to predict "what character comes next?" at every position, including learning that the next token after the last letter is BOS — i.e. "end of name". This is how a language model learns sequence boundaries.
3

Phase 3 — Model Initialisation

Every weight matrix in the model is filled with random numbers drawn from a Gaussian distribution (mean=0, std=0.08) using the seeded PRNG. Because the seed is fixed at 42, two runs produce identical results.

The model allocates roughly 21 000 individual Value objects just for its parameters — before any training even begins. This is the "blank brain" state: random noise that will be shaped by gradient descent.

4

Phase 4 — Forward Pass (repeated 1 000 times)

One name is picked from the shuffled list (cycling through all of them across 1 000 steps). It is converted to a token sequence, e.g. "emma" → [BOS, 4, 12, 12, 0, BOS].

For each position in the sequence, the GPT forward function runs: the token is embedded, a positional embedding is added, passed through one transformer layer (attention + MLP), and a final linear projection produces a 27-number logit vector — one score per possible next character.

At this stage the model is building a massive computation graph of Value nodes in memory. Every arithmetic operation creates a new node and records its children and local gradients. This invisible graph is what makes backpropagation possible.
5

Phase 5 — Loss Computation

The logits are converted to probabilities via softmax. The model's confidence in the correct next token is extracted and the cross-entropy loss is computed: -log(probability of correct token).

This is summed over every position in the name and averaged. A perfect model would score 0.0; a random model starts around 3.3 (≈ log₂(27)). As training proceeds you should see this number drop toward roughly 1.5–2.0.

6

Phase 6 — Backward Pass (Backpropagation)

loss.backward() is called. This walks the entire computation graph in reverse topological order, pushing gradients from the output (loss) back to every parameter. Each node receives a gradient signal telling it: "if you were slightly larger/smaller, how would the loss change?"

After this call, every parameter's .grad field holds the derivative of the loss with respect to that weight.

7

Phase 7 — Adam Optimiser Update

The Adam optimiser loops through all ~21 000 parameters, applies the adaptive gradient update, and then zeroes all gradients before the next step. The learning rate linearly decays from 0.01 → 0.0 over the 1 000 steps, ensuring stable convergence near the end of training.

The step number, loss, and a separator are printed to the console for every single step. Watching the loss drop is the primary feedback that the model is actually learning.

8

Phase 8 — Inference: Generating 20 Names

After all 1 000 training steps, the loop ends and the model switches to inference mode. Starting with only the BOS token, it generates one character at a time by sampling from the predicted probability distribution (scaled by temperature 0.5) until it predicts BOS again, signalling end-of-name.

Twenty such samples are printed. They should look like plausible — but entirely invented — English-sounding first names.

Example expected output:
sample 1: aveya
sample 2: lorna
sample 3: emmi

Section 1

Seeded PRNG — Mulberry32

lines 12 – 47

Machine learning requires randomness at two points: weight initialisation and data shuffling. But for a demo to be reproducible, that randomness must be deterministic. JavaScript's built-in Math.random() is unseeded — you can't control it — so a custom PRNG is included.

Mulberry32 is a fast, high-quality 32-bit PRNG. Given the same seed it always produces the same sequence of floats in [0, 1). The seed is hardcoded to 42. 

function mulberry32(seed: number): () => number {
  let s = seed | 0;
  return () => {
    s = (s + 0x6d2b79f5) | 0;
    let t = Math.imul(s ^ (s >>> 15), 1 | s);
    t = (t + Math.imul(t ^ (t >>> 7), 61 | t)) ^ t;
    return ((t ^ (t >>> 14)) >>> 0) / 4294967296;
  };
}
  • gauss(mean, std) — uses Box-Muller transform to turn two uniform random numbers into a Gaussian sample. This is how weight matrices are initialised with small random values.
  • shuffle(arr) — Fisher-Yates in-place shuffle. The names list is shuffled once at startup so each training step sees documents in a different order.
  • weightedChoice(weights) — samples an index proportional to its weight. Used during inference to pick the next token from the model's probability distribution.
Why does this matter? Without a seeded PRNG, every run would produce different results, making it impossible to compare or debug. With seed=42, every run is byte-for-byte identical.

Section 2

Autograd Engine — the Value class

lines 49 – 126

This is the most foundational piece of the entire file. Modern ML frameworks like PyTorch hide this behind abstractions, but here it is written from scratch in about 75 lines.

Every single number in the model — every weight, every activation, every intermediate result — is wrapped in a Value object. A Value stores:

  • .data — the actual floating-point number
  • .grad — the gradient that will be filled in during backward pass (starts at 0)
  • ._children — references to the Value nodes that produced this one (its "parents" in the computation graph)
  • ._localGrads — the local partial derivatives w.r.t. each child, pre-computed at operation time

Every arithmetic operation on a Value creates a new Value and records the dependency. This builds up an implicit computation graph in memory as the forward pass runs: 

// e.g. a.mul(b) creates a new Value whose children are [a, b]
// and whose local grads are [b.data, a.data] (by the product rule)
mul(other: Value | number): Value {
  const o = other instanceof Value ? other : new Value(other);
  return new Value(this.data * o.data, [this, o], [o.data, this.data]);
}

Operations supported: add, mul, pow, log, exp, relu — plus derived helpers neg, sub, div.

How backward works:

  1. The graph is traversed depth-first to produce a topological ordering — leaves first, output last.
  2. The output node's gradient is set to 1.0 (d(loss)/d(loss) = 1).
  3. The list is iterated in reverse, and for each node, its gradient is multiplied by each child's local gradient (chain rule) and accumulated onto the child's .grad.
Chain rule: ∂L/∂child += (∂L/∂node) × (∂node/∂child)
i.e.: child.grad += node.grad × localGrad
This creates millions of tiny JavaScript objects per training step — which is intentional. The project's benchmarking goal is to measure how fast different JS runtimes can allocate and GC small objects. Bun (JavaScriptCore) allocates them ~1.63× faster than Node.js (V8).

Section 3

Model Helpers — linear, softmax, rmsnorm

lines 128 – 149

Three building-block functions used throughout the transformer. They all operate on arrays of Value objects so gradients flow through them.

linear(x, w) — Matrix-vector multiplication

// For each output neuron (row of w), compute dot product with input x
function linear(x: Value[], w: Value[][]): Value[] {
  return w.map((wo) =>
    wo.reduce((acc, wi, i) => acc.add(wi.mul(x[i])), new Value(0))
  );
}

This is how all the weight matrices in the model are applied: query/key/value projections in attention, the two MLP layers, and the final language-model head all use this function.

softmax(logits) — Convert scores to probabilities

softmax(xᵢ) = exp(xᵢ - max(x)) / Σ exp(xⱼ - max(x))

The - max(x) is a numerical stability trick: subtracting the maximum value before exponentiation prevents overflow without changing the final probabilities. The output is a probability distribution summing to 1.

rmsnorm(x) — Root Mean Square Normalisation

RMSNorm(x) = x / sqrt(mean(x²) + ε)

Normalises the activations so they don't blow up or vanish as they pass through layers. This is applied at the start of each transformer layer and immediately after the input embeddings are created. ε = 1e-5 prevents division by zero.

Section 5

GPT Forward Pass

lines 210 – 267

The gpt(tokenId, posId, keys, values) function is called once per token position during both training and inference. It takes one token and one position and returns the 27 logit scores for the next token.

Step A — Input Embedding

The token's embedding vector (row tokenId of wte) and position's embedding vector (row posId of wpe) are added element-wise. This gives the model both what the token is and where it appears in the sequence. 

let x = tokEmb.map((t, i) => t.add(posEmb[i]));
x = rmsnorm(x);

Step B — Transformer Layer (repeated N_LAYER times)

The single transformer block has two sub-components, each with a residual connection:

  • Multi-head self-attention — the input is projected to queries (Q), keys (K), and values (V). Keys and values from all previous positions are cached and reused, so the model can "look back" at past context. Each of the 4 heads independently computes attention over a 4-dimensional subspace. The outputs are concatenated and linearly projected back to 16 dimensions.
  • MLP feedforward network — a two-layer network that expands 16 → 64, applies ReLU nonlinearity, then contracts 64 → 16. This is where the model stores and transforms factual associations.

Attention in detail:

scores = Q · Kᵀ / √HEAD_DIM
weights = softmax(scores) ← how much to attend to each past token
output = weights · V ← weighted sum of past value vectors

The 1 / HEAD_DIM ** 0.5 scaling factor prevents the dot products from growing so large that softmax saturates to near-zero gradients.

Step C — Language Model Head

After the transformer layer, a final linear call projects the 16-dimensional output vector to 27 logits — one per vocabulary token. These are the raw unnormalised scores that the loss function and inference sampler will operate on.

Section 6

Training Loop & Loss

lines 269 – 313

The training loop runs for exactly 1 000 steps. Each step processes one name document.

Tokenisation per step:

const tokens = [BOS, ...doc.split("").map((ch) => uchars.indexOf(ch)), BOS];
// e.g. "ava" → [26, 0, 21, 0, 26]
//               BOS  a   v   a  BOS (end signal)

The model is trained to predict the next token at every position — this is called teacher forcing. At position posId the input is tokens[posId] and the target is tokens[posId+1].

Cross-entropy loss:

loss = -mean( log( P(correct token) ) )

P(correct token) is extracted from the softmax output. If the model is 100% confident on the right answer, log(1.0) = 0. If it assigns near-zero probability, log(ε) → -∞. The loss penalises wrong confident predictions most severely.

After loss.backward(), every parameter has a non-zero .grad telling it which direction to move to reduce the loss.

Section 7

Adam Optimiser

lines 270 – 307

Adam (Adaptive Moment Estimation) is the standard optimiser for neural networks. Rather than using the raw gradient, it maintains two running averages per parameter and uses them to adaptively scale each update.

SymbolValueMeaning
lr0.01Base learning rate (step size)
β₁0.85Exponential decay for first moment (gradient mean)
β₂0.99Exponential decay for second moment (gradient variance)
ε1e-8Small constant to prevent division by zero

The update rule for each parameter:

m = β₁ × m + (1 - β₁) × grad ← running mean of gradient
v = β₂ × v + (1 - β₂) × grad² ← running mean of squared gradient
m̂ = m / (1 - β₁ᵗ) ← bias-corrected mean
v̂ = v / (1 - β₂ᵗ) ← bias-corrected variance
param -= lr_t × m̂ / (√v̂ + ε)

The bias corrections (1 - β₁ᵗ, 1 - β₂ᵗ) compensate for the fact that m and v start at zero — without them, early steps would be dramatically under-scaled.

Learning rate decay: lr_t = 0.01 × (1 - step / 1000) — a linear schedule from 0.01 at step 0 to 0.0 at step 1000. This helps the model make bold updates early and fine adjustments late.

The first and second moment arrays (m, v) are stored as Float64Array — plain typed arrays, not Value objects — since they don't need gradients.

After the Adam update, every p.grad is zeroed to prevent gradients from accumulating across steps. Forgetting this is a classic bug in from-scratch implementations.

Section 8

Inference — Generating Names

lines 316 – 337

Once training is complete, the model is used autoregressively to generate new names it has never seen. The process:

  • Start with tokenId = BOS and posId = 0
  • Run the GPT forward pass to get 27 logits
  • Divide each logit by the temperature (0.5) — lower temperature makes the distribution sharper / more confident
  • Apply softmax to get probabilities
  • Sample using weightedChoice — higher-probability tokens are more likely but not guaranteed
  • If the sampled token is BOS → stop (end of name)
  • Otherwise, append the character and repeat from the new position
P(token) = softmax(logits / temperature)

temperature = 0.5 → sharper, more conservative names
temperature = 1.5 → flatter, more creative / chaotic names
This is exactly how ChatGPT and every other autoregressive language model generates text — just at a much larger scale. The same "embed → attend → project → sample → repeat" loop runs billions of parameters deep for real models.

A fresh keys and vals KV-cache is created for each sample so that the 20 generated names are independent of each other.
